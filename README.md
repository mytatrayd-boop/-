# راصد (Rased) — تطبيق جوال

يرشّح **أقوى سهمين** أسبوعيًا من قائمتك: سيولة غير طبيعية (بوابة إلزامية) × زخم RSI(14)، مع دخول/هدف/وقف وفلتر يقين الشرعي. التطبيق PWA يُثبَّت كأيقونة على الجوال (iPhone: مشاركة ← إضافة للشاشة الرئيسية، Android: تثبيت التطبيق).

> ليس توصية مالية. المنطق **لم يُختبر تاريخيًا**.

## التشغيل

```bash
cp .env.example .env      # ضع ALPHA_VANTAGE_KEY (من alphavantage.co)
npm start                 # http://localhost:3000
npm test
```

بدون مفتاح يشتغل الخادم في **وضع تجريبي** ببيانات مصطنعة، وتُوسم في الواجهة بوضوح ("وضع تجريبي" / "بيانات تجريبية").

لا توجد أي مكتبات خارجية — Node 18+ فقط. أي استضافة Node تكفي (Railway / Render / Fly): أمر التشغيل `npm start` ومتغير البيئة `ALPHA_VANTAGE_KEY`.

## تجربة سريعة بدون خادم

```bash
npm run build:standalone   # → dist/rased-standalone.html
```

ملف واحد فيه التطبيق كاملًا بوضع تجريبي (نفس الواجهة ونفس منطق المسح في `server/scan.js`، مع بيانات مصطنعة). مناسب للمعاينة على الجوال أو النشر كـ Claude Artifact.

## البنية

| الملف | الدور |
|---|---|
| `server/engine.js` | منطق النموذج الأولي منقول كما هو: `barsFromAlphaVantage` (JSON + CSV)، `scoreTicker`، `buildTrade`، فلتر يقين |
| `server/alphavantage.js` | جلب الأسعار والأخبار وتقويم الأرباح بالمفتاح (يبقى في الخادم فقط)، طابور بفاصل 1.1 ثانية (حد الثانية الواحدة)، تخزين مؤقت (4 ساعات، والأرباح 24 ساعة)، كشف تجاوز الحصة |
| `server/scan.js` | تنسيق المسح (أسعار → سيولة → أخبار → أرباح → ترتيب)، بدون اعتماد على Node — يشغّله الخادم والنسخة المستقلة |
| `server/index.js` | خادم HTTP: `POST /api/scan`، `GET /api/health`، ويخدم `public/` |
| `public/` | واجهة الجوال: الترشيحات، كل الأسهم، يقين، الإعدادات |

## شاشات التطبيق

- **الترشيحات**: بطاقة لكل سهم (أعلى 2) — الاتجاه، **مصدر الترشيح** (سيولة / فني / خبر مع أهم العناوين)، تنبيه أرباح داخل الأسبوع، الدخول والهدف والوقف مع النسبة، شارت شموع 60 يوم، حكم يقين ورابط التحقق.
- **كل الأسهم**: نتيجة كل سهم (مؤهّل / سيولة ضعيفة / خبر معاكس / فشل / مستبعد بيقين) مع أثر الخبر.
- **يقين**: حكم لكل سهم بضغطة (ضغطة ثانية = غير معروف) + مفاتيح الاستبعاد.
- **الإعدادات**: قائمة المسح (حد 25) مع حساب استهلاك الحصة، بوابة السيولة، الأخبار، معاملات الصفقة. كلها محفوظة على الجهاز.

## التسجيل

```
1. بوابة السيولة (إلزامية): حجم اليوم ÷ متوسط N يوم (باستثناء اليوم) ≥ المضاعف، وإلا النتيجة صفر
2. RSI(14): الاتجاه (≥50 صاعد) وقوة الزخم |RSI−50|/50
3. النتيجة الأساسية = نسبة السيولة × قوة الزخم
4. الخبر (NEWS_SENTIMENT) — بوابة لينة + تعزيز، فقط لمن اجتاز السيولة، الأقوى أولاً حتى newsMax طلب:
   - المشاعر = متوسط مشاعر المقالات للسهم مرجّح بالصلة (صلة ≥ 0.3، آخر newsDays يوم)
   - المتوافق = المشاعر × الاتجاه
   - متوافق ≤ −حد الاستبعاد (0.35) → مستبعد
   - وإلا النتيجة × (1 + clamp(متوافق/الحد, −1, 1) × أقصى تعزيز)   → من ×0.5 إلى ×1.5 افتراضيًا
   - لا يوجد خبر / لم يُفحص / فشل الجلب → ×1 (محايد)، ويُعرض السبب صراحة
5. الأرباح (EARNINGS_CALENDAR، طلب واحد للسوق): تنبيه مخاطرة لو الإعلان داخل 7 أيام — لا يغيّر النتيجة
6. الترتيب تنازليًا، أقوى سهمين
```

أسوأ استهلاك لمسح واحد: عدد الأسهم + min(newsMax، عدد الأسهم) + 1. القائمة الافتراضية: 12 + 5 + 1 = 18 من 25.

### ما لم يُتحقق منه بعد ⚠️

- **شكل رد `NEWS_SENTIMENT` الكامل** (`feed[].ticker_sentiment[]`) مبني على التوثيق — الحصة كانت منتهية وقت الكتابة. المحلل دفاعي (أي مقال ناقص يُتجاهل، وأي رد بدون `feed` = خطأ واضح)، لكن لازم مسح حي واحد للتأكد.
- **ترويسة `EARNINGS_CALENDAR` مؤكدة** من رد حقيقي. ولوحظ فعليًا أن رسالة تجاوز الحصة ترجع أحيانًا مقطّعة كصف CSV (`I,n,f,o,r,m,a`) — المحلل يرفضها.

## الخطوات التالية

1. مسح حي واحد للتحقق من شكل رد الأخبار.
2. اختبار تاريخي صارم (الدخول بسعر الشمعة التالية، عمولة وتكلفة) قبل الثقة بأي نتيجة.
3. السوق السعودي — يحتاج مزوّد بيانات.
