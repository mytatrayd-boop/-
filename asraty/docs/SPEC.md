# أسرتي (Asraty) — مواصفات التطبيق

## 1. الفكرة
تطبيق لتنظيم مهام البيت والروتين اليومي للأسرة بأسلوب التحديات والنقاط. المسؤول يوزّع المهام، والأفراد ينجزونها ويكسبون نقاطاً، وتفتح النقاط مستويات مكافآت يحددها المسؤول. التطبيق عربي بالكامل (RTL) وموجّه للأسر السعودية.

المرجع البصري والسلوكي لكل ما يلي: `design/prototype.html`.

## 2. الأدوار والصلاحيات
| الدور | الوصف |
|---|---|
| `owner` مسؤول الأسرة الرئيسي | ينشئ الأسرة، ويملك كل الصلاحيات، وهو الوحيد الذي يضيف مسؤولين ويعدّل صلاحياتهم، ويرسل التنبيهات، ويدير الجوائز والمكافآت |
| `admin` مسؤول مفوَّض | يملك فقط الصلاحيات التي فعّلها له المسؤول الرئيسي |
| `member` عضو | ينجز المهام ويشارك في المسابقات ويرى مكافآته وتنبيهاته |

الصلاحيات القابلة للتفويض (مفاتيح `perms`):
- `addMembers` إضافة أعضاء للأسرة
- `approve` الموافقة على إنجاز المهام
- `tasks` إضافة وتعديل وحذف المهام
- `report` إرسال تقرير الترتيب اليومي
- `comps` إنشاء مسابقات
- `viewReports` الاطلاع على التقارير (وحدها = مسؤول للاطلاع فقط)

كل المسؤولين (بمن فيهم بلا صلاحيات) يرون مهام الأفراد عرضاً فقط.

**قرار مفتوح:** هل تصبح «إرسال التنبيهات» و«إدارة المكافآت» صلاحيات قابلة للتفويض؟ حالياً للمسؤول الرئيسي فقط.

## 3. التسجيل والربط بالبريد الإلكتروني
- الشاشة الأولى: خياران «مسؤول الأسرة» و«أحد أفراد الأسرة».
- **مسؤول جديد بدون أسرة:** يدخل اسم الأسرة واسمه وبريده ← يصله كود ← يتحقق ← تُنشأ الأسرة ويصبح `owner`.
- **إضافة عضو أو مسؤول:** المسؤول يدخل الاسم والبريد والرمز (وللمسؤول: الصلاحيات) ← يُنشأ سجل بحالة `invited` ← يُرسل كود لبريد الشخص فوراً مع شرح طريقة الربط.
- **دخول المدعو:** يختار نوع حسابه، ويدخل بريده، ثم الكود ← تتحول حالته إلى `active` ويرتبط بالأسرة.
- **رسائل الخطأ** (من النموذج): بريد غير مضاف، أو مضاف بدور آخر (يُوجَّه للخيار الصحيح)، أو كود خاطئ أو منتهٍ.
- الكود: 6 أرقام، صالح 30 دقيقة، 5 محاولات كحد أقصى، مع إمكانية إعادة الإرسال وحد لعدد مرات الإرسال.

**التنفيذ المقترح:** Callable Functions `requestCode(email, role)` و `verifyCode(email, code)`. الأولى تخزّن تجزئة الكود وترسله بالبريد. الثانية تتحقق، وتربط `authUid` بسجل العضو، وتعيد Firebase Custom Token مع claims تحوي `familyId` و`role`. بعدها يسجّل التطبيق الدخول بـ `signInWithCustomToken`.

الدعم حالياً لأسرة واحدة لكل بريد.

## 4. لوحة المسؤول
إحصاءات أعلى اللوحة (الأعضاء، ونقاط اليوم، والمسابقات الجارية) ثم خانات تظهر حسب الصلاحية:
1. **الموافقات** (`approve`) — مهام ومشاركات مسابقات بانتظار الموافقة، مع عدّاد. صورة الإثبات تظهر مصغّرة وتتكبر بالضغط، مع أزرار موافقة ورفض.
2. **إضافة مسؤول أسرة** (owner) — نموذج مع شبكة الرموز وخانات الصلاحيات، وقائمة المسؤولين مع تعديل الصلاحيات مباشرة وإعادة إرسال الكود والإزالة.
3. **إضافة عضو أسرة** (`addMembers`) — الاسم، والرمز، والبريد، وقائمة الأعضاء مع الحالة (مرتبط / بانتظار التحقق).
4. **تقارير الإنجاز** (`viewReports` أو `report`) — تبويبان اليوم والأسبوع: مجموع نقاط الأسرة، وعدد الإنجازات، والترتيب بالميداليات، والمستوى الذي استحقه كل فرد.
5. **إرسال ترتيب اليوم** (`report`) — معاينة نص التقرير ثم إرساله كتنبيه لكل الأعضاء.
6. **مهام أفراد الأسرة** (الكل عرضاً، والتعديل بـ `tasks`) — إضافة مهمة (مع مهام جاهزة سريعة) لفرد أو لكل الأعضاء، وتعديل وحذف، وحالة كل مهمة (لم تُنجز / بانتظار / منجزة).
7. **إرسال تنبيه** (owner) — لعضو محدد أو للجميع مع نص حر، وسجل آخر ما أُرسل.
8. **المسابقات** (`comps`) — انظر §6.
9. **الجوائز والمكافآت** (owner) — انظر §7.

## 5. واجهة العضو
- بطاقة علوية: عملة ذهبية بنقاط الأسبوع، ونقاط اليوم، وشريط تقدّم مهام اليوم.
- تبويبات: **مهامي**، و**المسابقات** (عدّاد لما لم يشارك فيه)، و**المكافآت** (نقاطه والمستوى المستحق والمتبقي للمستوى التالي بشريط تقدّم)، و**التنبيهات** (عدّاد غير المقروء).
- زر «أنجزتها» يرسل المهمة للموافقة. زر 📷 بجانبه يرفق صورة إثبات **اختيارية** (من الكاميرا أو المعرض).
- المهام يومية (تتجدد كل يوم) أو أسبوعية (تتجدد كل أحد).

## 6. المسابقات
- المسؤول يحدد: العنوان، ونقاط المركز الأول (افتراضي 20)، ومؤقتاً اختيارياً بالدقائق.
- عند الإطلاق يصل تنبيه لكل الأعضاء.
- العضو يضغط «أنجزت!» فيُسجَّل ترتيبه حسب وقت الإرسال: الأول = 20، والثاني = 19، وهكذا (الحد الأدنى 1).
- **يُحسب الترتيب داخل Firestore transaction في Cloud Function** لمنع تساوي الترتيب عند الضغط المتزامن.
- النقاط تُضاف بعد موافقة المسؤول. الرفض لا يعيد ترتيب الباقين.
- العدّاد التنازلي يظهر للجميع، ولا تُقبل مشاركة بعد انتهاء الوقت (التحقق على الخادم). يمكن للمسؤول إنهاء المسابقة يدوياً.

## 7. مستويات المكافآت
- كل مستوى: اسم، وأيقونة، وحد أدنى من النقاط، وفترة (يومية / أسبوعية)، ونطاق (لكل فرد / لمجموع نقاط الأسرة).
- الفرد يستحق **أعلى** مستوى وصل حده فقط ضمن نفس الفترة والنطاق. مثال: 66 نقطة أسبوعياً = نزهة، و30 = وجبة خارجية.
- قسم «المستحقون الآن» مع زر «تم التسليم» يُسجَّل لكل مستوى وفرد وفترة.
- النقاط لا تُصرف. هي مجموع ما كُسب داخل الفترة الحالية.

## 8. عناصر مشتركة
- **رأس التطبيق:** الشعار واسم الأسرة. تحته دوائر أفراد الأسرة: الرمز يملأ الدائرة كاملة باهتاً كعلامة مائية بدون اسم عليه (الاسم يظهر عند الضغط المطوّل وفي قارئ الشاشة)، مع إطار ذهبي. دائرة المدعو غير المرتبط إطارها منقّط وباهتة. الدوائر تلتف لأكثر من سطر عند الحاجة.
- **الرموز الكرتونية:** 12 رمزاً خاصاً بالتطبيق (أب بشماغ، أب بغترة، جد، أمّان بحجاب، جدة، شاب بكاب، ولد بطاقية، ولد، بنت بحجاب، بنت بضفيرتين، طفل). لا توجد صور شخصية. كل فرد يغيّر رمزه بنفسه، والمسؤول الرئيسي يغيّر للجميع، ومن يملك `addMembers` يغيّر للأعضاء.
- **اقتراحات وشكاوى 💬:** متاح قبل الدخول وبعده. نوع الرسالة (اقتراح / شكوى / مشكلة تقنية) ونصها، ويكتب الزائر بريده اختيارياً. تُحفظ في `feedback` وترسلها Function إلى `asraty200@gmail.com` مع المرسل والدور والأسرة ونوع الجهاز. تظهر للمستخدم آخر 3 رسائل أرسلها.
- **الإشعارات (FCM):** مهمة بانتظار الموافقة ← لمن يملك `approve`. موافقة أو رفض ← للعضو. تنبيه أو تقرير أو مسابقة جديدة ← للمستهدفين. تظهر كإشعار منبثق مع نغمة (مثل تطبيقات المحادثة): قناة Android `asraty_alerts` بأهمية قصوى، وعلى iPhone بانر مع صوت، وتظهر كذلك والتطبيق مفتوح.

## 9. نموذج البيانات (Firestore)
```
families/{familyId}                      name, ownerPersonId, createdAt
families/{fid}/people/{personId}         name, email, role, perms{}, avatar, status, authUid, fcmTokens[]
families/{fid}/tasks/{taskId}            title, personId, points, repeat(daily|weekly), createdBy
families/{fid}/completions/{taskId_periodKey}  taskId, personId, title, points, periodKey, status(pending|approved|rejected), photoPath?, createdAt, decidedBy?
families/{fid}/ledger/{id}               personId, delta, reason, source(taskId|compId), dayKey, weekKey, createdAt   ← server-only writes
families/{fid}/summaries/{personId_periodKey}  personId, periodKey, points, count   ← يُحدَّث مع كل قيد في ledger (نفس الـ transaction)
families/{fid}/competitions/{id}         title, startPoints, deadline?, ended, createdAt, entryCount,
                                         entries{personId: {rank, points, status, createdAt}}   ← الترتيب داخل transaction
families/{fid}/tiers/{id}                name, emoji, threshold, period, scope(each|family)
families/{fid}/deliveries/{tierId_who_periodKey}  deliveredBy, at    (who = personId أو family)
families/{fid}/notifications/{id}        to('all'|personId), title, body, from, createdAt, readBy[]
emailIndex/{emailLower}                  familyId, personId, role        ← server-only
authCodes/{sha256(email)}                codeHash, expiresAt, attempts, sentCount, windowStart, sentAt, setup?   ← server-only
feedback/{id}                            type, text, email?, familyId?, personId?, role?, platform, createdAt
```
- معرّف مستخدم Firebase Auth = `personId`، والـ custom claims تحوي `familyId` و`role`.
- العميل يقرأ فقط (قواعد Firestore)، وكل كتابة عبر الدالة `api` (callable) التي تتحقق من الصلاحيات.
- المشاركات في المسابقة محفوظة داخل وثيقة المسابقة (بدل subcollection) ليُقرأ كل شيء بمستمع واحد، مع بقاء الترتيب آمناً داخل transaction.
- `periodKey`: يومي `2026-09-29`، أسبوعي `w2026-09-27` (تاريخ الأحد)، بتوقيت الرياض.

## 10. مراحل البناء
1. **الأساس:** مشروع Flutter + Firebase + المحاكيات، والثيم والخطوط والرموز، وشاشة الاختيار، ودخول الكود بالبريد، وإنشاء الأسرة، وإضافة الأعضاء والمسؤولين بالصلاحيات، وقواعد الأمان.
2. **الجوهر:** المهام، والإنجاز، والموافقات، والنقاط (ledger)، وواجهة العضو، ورأس التطبيق بالحلقات.
3. **التحفيز:** مستويات المكافآت والتسليم، والتقارير، وإرسال ترتيب اليوم، والتنبيهات، والإشعارات.
4. **المسابقات** وصور الإثبات الاختيارية.
5. **الإطلاق:** الاقتراحات والشكاوى، وحذف الحساب والأسرة، والوضع الليلي، والأيقونات (مع نسخة Android adaptive بهامش أوسع)، وشاشة البداية، وسياسة الخصوصية، والنشر التجريبي (TestFlight / Internal testing).

## 11. خارج نطاق النسخة الأولى
الدفع والاشتراكات، وشراكات المتاجر (القسائم)، وحزم المهام المدفوعة، وتعدد الأسر لنفس البريد، والتحويل الكرتوني للصور.
